Solving 400 grid puzzles with the smallest possible models

A code-golf competition where correctness is the entry fee and every byte is a cost. This is a short account of the problem, the method we used to minimize, and what we found.

01

Background: the competition

Each of the 400 tasks is an ARC-style reasoning puzzle: a handful of worked examples, each an input grid of coloured cells and the output grid it should map to. Grids are up to 30×30, with ten colours. The examples come in three sets — train, test, and a larger machine-generated arc-gen set — and a task pays out only if the submitted model is exact on all of them. One wrong cell anywhere scores the task zero.

The submitted object is not a program but an ONNX model: a computation graph that takes the input grid, one-hot encoded to a (1, 10, 30, 30) tensor, and produces an output tensor of the same shape that is thresholded and cropped back to a grid. Any graph that computes the right function is legal, whatever operators it uses.

What makes it golf is the scoring. A solved task is worth:

points = max(1.0, 25.0 − ln(memory_bytes + parameters))

Correctness gets a task onto the board; after that, the only variable is size. Because the penalty is the natural logarithm of the model's cost, halving a model is always worth the same ≈0.69 points — whether it drops from 30,000 bytes to 15,000 or from 20 to 10. The theoretical maximum per task is 25 points, reached only at zero cost.

With 400 tasks and a 25-point ceiling each, the competition's headroom is about 10,000 points. Reaching it means not just solving every puzzle, but solving each one with a model small enough to give up almost nothing.

03

How we minimized

The method was a loop. Identify the rule a task follows; express that rule as the smallest exact ONNX graph we could; then rewrite the graph repeatedly, keeping any change that reduced cost and provably preserved the output. Five levers did most of the work.

i

Read the cost function literally

Cost is the sum of every intermediate tensor's byte size plus the parameter count. Crucially, a model's input and output tensors are free, and initializers are charged by element count only. A graph that writes straight from one operator to the output, holding nothing in between, can cost almost nothing.

ii

Prefer one operator to a network

Most rules don't need layers. A tiling is a single Einsum; a colour remap is one Gather; a reflection is a Slice. We built a library of rule families and, for each task, emitted the fewest nodes that computed it exactly. 103 of the 400 final models are a single node.

iii

Pick the cheapest dtype

Tensors are billed by their data type's width: an int64 costs 8 bytes per element, a bool just 1. Demoting intermediates to the narrowest type that still computes correctly — and packing the ten colour channels into integer bit-planes — cut the memory of the heavier models several-fold.

iv

Golf the graph, then golf it again

Dead-node elimination, constant folding, and common-subexpression removal each shrink a graph — and each opens rewrites the others couldn't reach. Optimization behaved like a fixpoint: re-running the passes on an already-golfed graph kept paying, so we iterated rather than swept.

v

Gate every change on proven equivalence

A smaller graph is only worth adopting if it computes the same function. Every rewrite was verified against all examples plus randomized probes before promotion. This is why local estimates matched the public score to the hundredth on every submission — nothing shipped that hadn't been proven exact first.

04

Results

The finished pack reproduces all 400 tasks. Its size profile shows where the method reached: a long tail of near-free models, and a small cluster of heavyweights on tasks whose rules resisted a compact form.

Median model cost sits under 700. Bitwise operators dominate the operator count — packing colour channels into integer bit-planes is far cheaper than carrying float tensors. The twenty models above 10,000 hold most of the remaining unclaimed points.

05

Findings

A few results shaped the whole effort, and were logged as carefully as the wins so no dead end cost us twice.

●

Only generalizing rules count. A model that merely memorizes the shown examples passes local checks but scores zero on the hidden set. Every point earned came from a rule that genuinely generalizes — and each of those transferred at exactly its predicted value.

●

Free input/output is the deepest lever. Because a graph's boundary tensors aren't charged, the cheapest models do their entire computation in a single node writing straight to the output. This one fact, read directly from the cost function, mattered more than any architectural idea.

●

There is no accounting loophole. We probed the cost harness for undercounted tensors and cheaper-than-advertised encodings; every one charged correctly. The only thing that moves the score is honestly re-deriving a smaller exact graph.

●

Optimization is a fixpoint, not a pass. Re-running the golf passes on a freshly-changed graph keeps finding savings, because each rewrite legalizes the next. Some tasks gave up new reductions on their third and fourth visits.

06

Where it ended

The final submission scored 7398.77 — rank 297 of 3,061, inside the bronze band by a small margin. Every one of the campaign's gated submissions graded at exactly its local prediction, which is the outcome the equivalence-gating was built to produce.

The distance to the top is not mysterious, which is the interesting part: the leaders average roughly 173 cost per task against our 683. They are not doing something fundamentally different — they are carrying the same minimization further, onto the heavyweight tasks we left standing. That gap is the clearest map of where the next points are.
