Beating Balatro with a bit-exact simulator and four billion hands

How a 1.1M-parameter transformer learned to win LocalThunk's poker roguelike — by first rebuilding the entire game in Rust, bit for bit, and then playing it four billion times.

Balatro is a poker-flavored roguelike deckbuilder: long runs, sparse rewards, heavy randomness, and a combinatorial action space — a genuinely hard target for reinforcement learning. The real game steps far too slowly to train against, so the project's core wager was fidelity: reimplement the game as a headless Rust simulator faithful to the original down to its random-number generator, train against that at tens of thousands of steps per second, then hold the result to account against the genuine article. The certified policy wins 71.0% of full runs (ante 8, White Stake) over ~8,000 held-out seeds — far past the best previously published RL result for the game — and, driven live against real Balatro, piloted a 223-action run to an ante-8 victory with zero divergences between simulated and actual game state.

The game

Balatro (LocalThunk, 2024) hands you a standard 52-card deck and asks you to score poker hands. A run is eight antes; each ante is three blinds — Small, Big, and a Boss — and each blind is a chip target you must reach within a budget of four hands and a few discards. Beat the Boss Blind of ante 8 and the run is won. Fall short anywhere and it's over.

What makes it a deckbuilder is everything between blinds. The shop sells jokers — up to five persistent cards that warp the scoring rules (flat bonuses, per-suit triggers, retriggers, multipliers that grow as you play) — alongside planet cards that level up specific poker hands, tarot and spectral cards that mutate the deck itself, vouchers, and booster packs. Money is earned per blind and pays interest, so a run is also an economy: spend now, or bank toward compounding. Boss Blinds impose their own rules (debuffing a suit, forcing card draws, capping hand size), and each blind can instead be skipped for a tag with a delayed payoff.

For a learning agent this is a nasty combination: episodes run hundreds of decisions with the only true signal — win or lose — arriving at the very end; the shop is stochastic; and a single "action" can be a composite like choose these four of your eight cards, and discard rather than play them. There is no public environment for it, and prior RL attempts have topped out well short of consistent full-run wins.

The math of a run

Every played hand resolves to a single product. The hand type contributes base chips and base mult (a level-1 Flush is worth 35 × 4), each scoring card adds its rank value to the chip side, and then the jokers pile on — some add chips, some add mult, and the valuable ones multiply mult:

score = (base + card + joker chips) × (base mult + joker mult) × ∏ ×mult jokers

Play K♥ Q♥ 9♥ 6♥ 3♥ — a Flush. Base 35 chips plus card chips 10+10+9+6+3 gives 73; times base mult 4 scores 292. Add a joker worth +4 mult and another worth ×1.5: 73 × 8 × 1.5 = 876. Planet cards permanently raise a hand type's base values, one level at a time.

The property the whole project leans on: Balatro is fully deterministic given its seed. Every random event — shop contents, pack rolls, boss selection, card draws — pulls from a named stream. A stream's state is initialized by hashing its name with the run seed via the game's own string-hash:

num ← ( (1.1239285023 / num) · byteᵢ · π + π·i ) mod 1

iterated over the string's bytes from the end (pseudohash). Each draw advances the stream — s ← |round₁₃((2.134453429141 + 1.72431234·s) mod 1)|, where round₁₃ is a printf %.13f round-trip — averages it with the hashed seed, and feeds the result to LuaJIT's Tausworthe math.random.

All of this is IEEE-754 double arithmetic, which means it can be reproduced bit for bit in another language — same seed in, same shop out. That single fact is what makes a faithful external simulator possible at all.

Rebuilding Balatro, bit for bit

The real game is a LÖVE/Lua application with animations in the loop — fine for humans, hopeless for a training regime that needs billions of steps. So the environment is a from-scratch headless reimplementation in Rust: the full run loop, the scoring pipeline, the shop and pack economy, consumables, vouchers, tags, boss blinds, and all 150 jokers, exposed to Python as a vectorized environment that steps thousands of games in parallel.

Fidelity was treated as the product, not a nice-to-have. Every ported behavior cites the exact line of game source it mirrors; Lua's evaluation order and floating-point quirks (including that %.13f round-trip in the RNG) are preserved verbatim. The RNG layer was verified bit-exact against test vectors generated by a pinned, game-era LuaJIT build — a detail that mattered immediately, since the system LuaJIT on the development machine produces different random streams. Scoring, shop rolls, and joker triggers are all held to oracle vectors the same way: 294 tests stand between the simulator and quiet drift.

Passing your own tests is not the same as matching the game, though. The final gate is a cross-validation harness that plays the real Balatro (via the balatrobot mod) and the simulator in lockstep on the same seed, diffing the entire game state after every single action — every card, every joker, every dollar. Roughly 1,300 live-verified steps across seeded runs, three driving policies, and all eight antes ended with zero unexplained divergences. Getting there surfaced four real simulator bugs the unit tests could never have caught:

  • The Red Deck gives 4 discards, not 3. The deck's "+1 discard" applies to a base the code had wrong — an error that directly shaped every training episode, found only by diffing live state.
  • End-of-round cards return to the deck's front, not its back — a draw-order difference that compounds over a run.
  • Card debuffs clear the moment a blind is defeated, not at round end.
  • Rounds survived by Mr. Bones pay no blind reward — the sim was paying out on a technicality the game doesn't honor.

The harness also caught one discrepancy that turned out to be a bug in the game's own modding-framework beta rather than in the simulator — documented and normalized, not ported.

Four billion hands

The agent observes the game as entity tokens: one token per hand card (38 features — rank, suit, enhancement, edition, seal, debuff state), per joker, per consumable, per shop slot, plus the blind and a global state vector — with head-room reserved in every vocabulary so the encoding never has to break. A ~1.1M-parameter transformer attends over these tokens and acts through a composite, fully masked action space: a 25-way action-type head (play, discard, buy, sell, use, reroll, skip, cash out…) followed by conditional parameter heads, including an autoregressive pointer that selects cards from the hand one at a time until it emits STOP. Illegal choices are masked to zero probability, and only the heads the chosen type actually consumes are sampled.

Training is PPO, with the interesting work in the schedule rather than the algorithm:

  • Ante-ladder curriculum — episodes first end at ante 1, then 2, 3, 5, 8; the agent is promoted each time it clears a 70% win rate on held-out seeds, so it always trains at the frontier of what it can do rather than drowning in eight-ante failures.
  • Snapshot backward curriculum — a pool of mid-run save-states lets a fraction of episodes begin at ante 4 with a real economy already built (each restored future independently re-randomized, so memorization is impossible), giving late-game states training coverage they'd otherwise rarely earn. The fraction anneals to zero so the final regime is pure fresh starts.
  • Reward annealing — a dense per-blind shaping signal gets the policy off the ground, then is annealed away (β → 0.1) so what's optimized at the end is essentially the only thing that matters: winning the run.
  • Throughput engineering — bf16-autocast updates over fp32 master weights, torch.compile, and a GPU-resident rollout buffer, every toggle gated by bit-identical A/B tests against the plain trainer. ~10k env-steps/s on a desktop RTX 4070; ~48k on the rented 2×RTX-5090 box that ran the main schedule.

The full schedule was 4 billion environment steps, with a second seed trained from the same fork as a confirmation run — it matched the main run's learning curve at every checkpoint. A live A/B settled a config question mid-flight (2 PPO epochs beat 4, per step and per wall-clock hour). Certification at the end was deliberately boring: four late checkpoints, evaluated greedily on ~8,000 held-out seeds each, all landed between 70.7% and 71.1% — converged, not lucky.

Playing the real game

A policy that wins in your own simulator has proven exactly one thing: it can win in your simulator. The closing demonstration removes that asterisk. A bridge drives the actual game — the policy picks an action, the bridge executes it in real Balatro, and the simulator steps in lockstep, with the full-state diff from the cross-validation harness running after every action.

Watching it play is instructive. Each decision is a single forward pass — the 1.1M-parameter model is so small that inference is effectively free next to the game's animations. It plays the whole surface of the game: choosing which blinds to skip for tags, steering discards toward the hand types its jokers pay for, working the shop with sells and rerolls, and visibly playing the economy — the $99 it finished with is a policy that learned to sit above the interest cap and let compounding do quiet work across the run.

The lockstep run also earned its keep as an instrument: the only issues it surfaced were in the driving harness, not the models — the real game pays a stale dollar amount if "cash out" is pressed mid-animation, and the mod's use/sell commands silently no-op outside certain phases. Both are now handled, and the sim's model of the game stands unfalsified at every step it has ever been tested on.

Coda

The bet that paid off was putting the engineering rigor into the environment rather than the model. A 1.1M-parameter policy is modest by any standard; what it had that prior attempts didn't was four billion hands of an environment faithful enough that nothing learned there broke on contact with reality — zero divergences is not a rounding of "few," it is the number.

The natural extensions are all open: a larger model fine-tuned from the certified checkpoint, search on top of the policy (the simulator makes expectimax over shop outcomes cheap), and the harder deck-and-stake combinations beyond White Stake. The floor they'd build on — a verified, vectorized, bit-exact Balatro — is the part that was hard to get right, and it's done.
